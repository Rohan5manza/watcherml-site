THE MISSING LAYER

Trackers show you what happened.
WatcherML investigates why.

Metrics dashboards are useful after a clean run. WatcherML is built for the messy reality: CUDA OOMs, and — as the deterministic rule set grows — NaNs, stalled data loaders, poor GPU utilization, and regressions that need more than another chart.

NEAREST-SUCCESS DIFF

Compare against the right baseline automatically.

A documented, weighted similarity score — dataset fingerprint, model config, GPU, Git ancestry, config distance, framework versions, recency — picks the closest successful run, not just the most recent one, with a checklist explaining why.

✦
LOCAL OLLAMA ADVISOR (OPTIONAL)

Reason over evidence locally — or don't.

Ollama can rank memory-failure hypotheses and propose config patches, entirely on your machine. Every capability works with zero LLM involvement too — Ollama only ever adds a labeled explanation on top of a deterministic result.

↻
POLICY-GATED RECOVERY

Six knobs, hard trial caps, nothing else.

The recovery agent may only propose changes to batch_size, gradient_accumulation_steps, precision, sequence_length, gradient_checkpointing, and num_workers. Every proposed patch is validated against that allowlist before anything runs, and trial count is hard-capped regardless of what's requested.

✓
DETERMINISTIC EVALUATION

Let code decide whether a trial worked.

Candidates are probed cheaply first and eliminated if they still fail, before a full trial ever runs. The result — success, your goal metric, throughput, VRAM headroom — decides the winner, not the LLM's opinion of its own proposal.

⎇
RESOLUTION MEMORY

Remember fixes that survived reality.

Every verified trial across every campaign aggregates into "this failure signature, this fix, verified in N of M attempts" — built from data you already have the moment more than one campaign has run, not a separately maintained knowledge base.

DEFINE SUCCESS BEFORE AUTONOMY

Every recovery campaign runs against a contract.

Set a goal metric, a VRAM ceiling, and a trial budget. WatcherML stops when candidates run out, the budget is exhausted, or nothing survives probing — and tells you exactly why it stopped.

  • Explicit goal metric and direction
  • Maximum trials, hard-capped regardless of what's requested
  • Six-key allowlist enforced by a policy engine, not a prompt
  • Full audit trail — every trial is a normal, independently inspectable run
Python, not YAML (today)● real API
contract = watcher.RecoveryContract(
  goal_metric="val_accuracy",
  goal_direction="maximize",
  max_vram_gb=14.5,
  max_trials=6,
  probe_steps=30,
)

DESIGNED FOR THE TRAINING LOOP

A small recorder API. An opt-in recovery agent on top.

WatcherML is a useful recorder with zero agent involvement — the recovery agent is a separate, optional call.

Working todayEvery command below runs against the actual package — nothing aspirational.
import watcherml as watcher

with watcher.init(
    project="mistral-lora",
    config=config,
) as run:
    train(model, dataset, run=run)

# On failure: a forensic capsule is saved automatically,
# with deterministic diagnosis and evidence IDs.
# Recover from a CUDA OOM failure -- bounded, policy-gated
report = watcher.recover_from_oom(
    project="mistral-lora",
    failed_run_id=run.run_id,
    train_fn=train,
    contract=watcher.RecoveryContract(
        goal_metric="val_accuracy",
        max_trials=6,
    ),
)

# Inspect the full audit trail
watcher recoveries
watcher recovery report['campaign_id']
SAFE BY CONSTRUCTION

The agent never gets a blank check.

Autonomy without guardrails is just expensive uncertainty. Today that means a hard six-key allowlist and trial caps enforced in code, not a prompt — worktree/container isolation is the next safety layer, planned before any code-patch capability ships.

Read the design principles →
01Six-key allowlistbatch_size, precision, and four other config keys — nothing else, enforced by code.
02No open shellThe LLM only ever returns structured JSON proposals, never executes commands.
03Hard trial capsCapped regardless of what a campaign requests — verified by test, not just documented.
04Config-only, for nowNo code, dependency, or dataset changes — that's why isolation isn't built yet either.
05Private by defaultLocal inference; everything also works with zero LLM involvement.
06Deterministic verdictsSuccess, metrics, and VRAM headroom decide the winner — not the LLM's opinion.
